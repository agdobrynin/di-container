# 🧹 Сброс контейнера зависимостей.

Действие «сброса» контейнера зависимостей вернёт его в исходное состояние – очищая внутренний буфер
свойств и зависимостей до того же состояния, в котором они находились при первом создании контейнера,
например через [построитель контейнера DiContainerBuilder](06-container-builder.md).

## Полный сброс контейнера зависимостей.
Метод выполняющий сброс контейнера `reset()` может быть вызван как для рантайм контейнера, так и для
скомпилированного контейнера.

Выполнение сброса контейнера приведет
к сбросу всех определений контейнера [добавленных через хелпер функции](01-php-definition.md)
или [настроенных через PHP атрибуты](02-attribute-definition.md) т.е. они будут приведены в исходное состояние на момент инициализации контейнера,
так же будут очищены вспомогательные кэши этих определений.
Для [параметров контейнера](09-container-parameters.md) так же выполняется сброс.

> [!WARNING]
> [Рантайм определения контейнера](10-runtime-definition.md) (сервисы), [рантайм параметры контейнера](09-container-parameters.md#параметры-контейнера-определяемые-во-время-выполнения) добавленные контейнер
> будут недоступны после полного сброса контейнера. 
> Используйте повторную установку значений если они необходимы после сброса.
> 

```php
use Kaspi\DiContainer\DiContainerBuilder;

$container = (new DiContainerBuilder())
                ->import('App\\', '/app/src')
                ->load('/app/config/container/services.php')
                ->loadParameters('/app/config/container/parameters.php')
                ->build();

// ...

$container->reset();
```
