# 🧹 Сброс контейнера зависимостей.

Действие «сброса» контейнера зависимостей вернёт его в исходное состояние – очищая внутренний буфер
свойств и зависимостей до того же состояния в котором они находились при первом создании контейнера.

## Полный сброс контейнера зависимостей.
Метод `reset()` выполняющий «сброс» контейнера может быть вызван как для рантайм контейнера, так и для
скомпилированного контейнера.

Выполнение сброса контейнера приведет всю конфигурацию контейнера в состояние которое было
на момент первой инициализации. У всех определений [добавленных через хелпер функции](03-php-definition.md)
или [настроенных через PHP атрибуты](02-attribute-definition.md) так же будут очищены внутренние буферы свойств и вспомогательные кэши этих определений.

Для [параметров контейнера](container-parameters/index.md) так же выполняется сброс.

> [!WARNING]
> Для [рантайм определений контейнера](runtime-definition/index.md) (сервисы), [рантайм параметров контейнера](container-parameters/index.md#параметры-контейнера-определяемые-во-время-выполнения)
> так же будут сброшены установленные значения, они будут приведены в первоначальное состояние после полного сброса контейнера.
> Используйте повторную установку значений если они необходимы после сброса контейнера.
> 

```php
use Kaspi\DiContainer\DiContainerBuilder;

$container = (new DiContainerBuilder())
                ->import('App\\', '/app/src')
                ->load('/app/config/container/services.php')
                ->loadParameters('/app/config/container/parameters.php')
                ->build();

// ...

$container->reset();
```
